# Как пользоваться Korat MCP Hub

Этот документ предполагает, что оператор уже развернул Korat и сообщил его
HTTPS-адрес. Для локального запуска из исходников используйте
[getting-started.md](getting-started.md).

## Вход

Откройте `<cloud-url>/app/signin`. Развёртывание может включать вход через
GitHub, Google или magic link по email. Новому аккаунту обычно нужен инвайт;
первый администратор с настроенным bootstrap-email входит без него.

В стандартной консоли есть:

- **Overview** — состояние relay и основные счётчики;
- **MCP servers** — опубликованные локальные и зарегистрированные HTTP-серверы;
- **Access** — запросы, разрешения и подключённые OAuth-клиенты;
- **Activity** — активные и завершённые relay-сессии;
- **Runtimes** — работающие транспортные endpoints издателей.

Hosted agents, inference, channels и rooms — опциональные модули развёртывания;
в стандартную навигацию MCP relay они не входят.

## Авторизация CLI

```bash
korat login --cloud <cloud-url>
```

CLI откроет страницу подтверждения device flow. Отзывной CLI-токен не связан с
браузерной сессией. `korat logout` удаляет локальные credentials.

## Публикация локального MCP-сервера

```bash
korat mcp add my-server --command "<команда запуска сервера>"
korat up
```

`korat up` запускает публикующий runtime в foreground. Для установленного
бинарника `korat service install` создаёт постоянный фоновый publisher.

Доступность вычисляется по heartbeat и видна в командах:

```bash
korat status
korat runtimes
korat mcp list --ids
```

## Подключение MCP-клиента

Один агрегированный bridge для всего Space:

```json
{
  "mcpServers": {
    "korat-space": {
      "command": "korat",
      "args": ["connect", "--space", "--bridge", "--agent", "my-client"]
    }
  }
}
```

`my-client` — стабильная identity потребителя. Повторное использование имени
сохраняет его разрешения; разные имена получают независимые разрешения. Без
`--agent` CLI всегда использует identity `default`.

Первое подключение к серверу создаёт запрос доступа. Владелец разрешает или
отклоняет его в разделе **Access**. Отзыв разрешения немедленно закрывает
затронутые активные сессии.

## Безопасность аккаунта

В разделе **Account** проверяйте браузерные сессии, подключённые способы входа и
CLI-токены. Незнакомые credentials следует отозвать.
